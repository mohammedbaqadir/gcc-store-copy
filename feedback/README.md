# Feedback

This is how corrections to generated copy turn into permanent rule changes — without retraining anything.

## How it works

1. You review generated copy and find something wrong (wrong tone, missed a rule, bad phrasing choice, etc.)
2. You log it in `FEEDBACK.md` — what was wrong, what you'd write instead, and which file it likely belongs to
3. Periodically, you review the log and promote recurring issues into the actual project files: `STYLE.md`, `RULES.md`, `VOCABULARY.md`, `FORBIDDEN.md`, or `golden-set/`

## Who does this

You. This is a human-approved loop, not automatic. The agent doesn't edit its own rules — only you decide when a correction is worth making permanent.

## When to log something

Log it if it's a pattern, not a one-off. If the same issue shows up twice, it belongs here. If it's a one-time fluke, just fix that one product's copy and move on.

## When to promote it

Promote a logged item once you've seen it repeat, or once you're confident it's a real rule (not just a preference for one product). One correction is a note. Three similar corrections is a rule.
